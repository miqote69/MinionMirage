# Runtime state reporting test specification

| ID | Path | Action and oracle |
| --- | --- | --- |
| MNP-STATE-001 | Build | `dotnet restore --locked-mode`, then `dotnet build -c Release --no-restore`; both exit 0 with no errors. |
| MNP-STATE-002 | Load/heartbeat | Load the real Dev Plugin. `runtime-state.json` parses as schema 2, lists all four fixed mappings, and `observedAtUtc` advances within 5 seconds. |
| MNP-STATE-003 | No Companion | With no minion, `selectionState=no_companion` and `companions=[]`. |
| MNP-STATE-004 | Wrong Companion | Summon a Companion other than 331, 232, 218, or 398. Its `baseId` appears and `selectionState=source_not_present`; it is not tracked. |
| MNP-STATE-005 | Target ownership | Summon Companion 331, 232, 218, or 398. Exactly one entry reports `isOwnedByLocalPlayer=true`, an ownership reason, and `selectionState=target_ready`. |
| MNP-STATE-006 | Screenshot-identified Y'shtola redraw | Reject Glamourer `ui_config.json` `SelectedNpc` as current-Actor evidence. From the User-provided screenshot, fix the target as Battle NPC ID 13910 / Name ID 10570 and resolve Human BNpcBase 13910 through BNpcCustomize 526 and NpcEquip 2269. Summon Companion 331. The plugin writes that customize/equipment backing once, requests the normal full redraw without a global Create hook, applies `ModelScale=1.0f`, and reports `tracked.stage=Redrawn`, `targetKind=BattleNpc`, `targetRowId=13910`, and the requested/applied model scale. Human Y'shtola appearance and clothing require User confirmation; weapon replacement remains excluded. |
| MNP-STATE-007 | Despawn/recovery | Dismiss the target. Tracking clears and selection returns to a no-target state without modifying another Companion. |
| MNP-STATE-008 | Unload | Unload with target present. The final snapshot reports `pluginState=disposed`; restoration remains separately confirmed from log/runtime observation. |
| MNP-STATE-009 | Atomic reader | Repeated background JSON reads during state changes never observe partial or malformed JSON. |
| MNP-STATE-010 | Monster redraw | Summon Companion 232. ModelChara `1689` backing is written and the normal full redraw is requested without Human-specific judgment or finalization; `tracked.stage=Redrawn`. Monster and visual confirmation remain separate observations. |
| MNP-STATE-011 | Monster lifecycle | Dismiss and resummon Companion 232. Original minion restoration/despawn remains normal and the BOSS appearance is reapplied once. |
| MNP-STATE-012 | Clothed Alisaie NPC redraw | Summon Companion 218. ENpcBase 1017687 resolves the Anamnesis-matching NPC appearance with Body `74650` (`0x1239A`, `e9114`), Hands `75439` (`0x126AF`), Legs `74650` (`0x1239A`), and Feet `74650` (`0x1239A`). The plugin writes ModelChara/customize/equipment backing once, calls the normal `DisableDraw` / `EnableDraw` full redraw, then writes `0.97f` to the recreated `CharacterBase.ModelScale` (`CharacterBase+0x2A4`) to match the User-confirmed current player multiplier. No global Create hook, immediate Human/RaceSexId/equipment judgment, post-create equipment API, or failure-triggered rollback is permitted. Completion reports `tracked.stage=Redrawn`, `targetKind=EventNpc`, `targetRowId=1017687`, and the requested/applied model scale; clothing, Human appearance, and relative height require User confirmation. Weapon replacement is excluded. |
| MNP-STATE-013 | Alisaie NPC lifecycle | Capture the original Companion draw-model scale, summon/convert Companion 218, then dismiss and resummon it or unload the plugin. The target receives `ModelScale=0.97f`; normal restoration receives the captured original scale, and the clothed Alisaie NPC appearance plus `0.97f` scale is reapplied once after resummon. |
| MNP-STATE-014 | Mapped Companion switch stabilization | With mapped Companion 218 displayed as Alisaie, summon Companion 232. If the same Actor slot reports BaseId 232 while its backing ModelChara is not the Companion-sheet source model `1782`, the plugin reports `source_model_pending` and performs no Scathach redraw. It applies BNpcBase 6479 only after backing ModelChara `1782` is present. The reverse switch waits for Companion 218 source ModelChara `1617` before applying ENpcBase 1017687. No target NPC may flash during either transient backing state; final visual confirmation is User acceptance. |
| MNP-STATE-015 | Screenshot-identified Gaia redraw | From the User-provided screenshot, fix the target as BattleNpc `17830` / ModelChara `4436`, category DemiHuman, Type `2`, Model `1041`, Base `1`, Variant `1`. Summon Companion `398`. The plugin waits for the Companion-sheet source ModelChara, resolves and writes ModelChara `4436` plus BNpcBase `17830`'s `BNpcCustomize` and `NpcEquip` creation inputs, requests the normal full redraw through the dedicated DemiHuman branch without Human post-create equipment-slot processing, and reports `tracked.stage=Redrawn`, `targetKind=BattleNpc`, `targetRowId=17830`, `targetModelCharaRowId=4436`, and `modelType=DemiHuman`. The Gaia NPC appearance in the screenshot requires User confirmation; ModelChara alone is not the visual oracle. |
| MNP-STATE-016 | Gaia lifecycle | Dismiss and resummon Companion `398`. Original minion restoration/despawn remains normal and BNpcBase `17830` / ModelChara `4436` is reapplied once after the source model becomes ready. |
| MNP-STATE-017 | DemiHuman/Monster separation regression | Resolve Gaia BNpcBase `17830` and Scathach BNpcBase `6479` through the production resolver. Type `2` Gaia fails closed if either `BNpcCustomize` or `NpcEquip` is unavailable and otherwise carries both arrays into redraw. Type `3` Scathach remains model-only and does not acquire DemiHuman customize/equipment handling. Runtime visual acceptance for Gaia and Scathach remains separate User observation. |
| MNP-UI-001 | Default and persistence | With no prior config, all four fixed mappings are enabled. Disable one mapping in the actual configuration window, close/reopen the window or reload the plugin, and verify only that mapping remains disabled while the other three remain enabled. No extra mappings or settings are created. |
| MNP-UI-002 | Row content | Open the actual configuration window. Exactly four mapping rows appear in fixed contract order. Each row shows the source Companion's real game icon and localized Companion-sheet name plus one visible enabled/disabled checkbox state. Missing icon data degrades to the name and control without crashing. |
| MNP-UI-003 | Language selection | Select Automatic, English, Japanese, German, and French in turn. UI labels and language names change immediately and persist. Automatic follows `IClientState.ClientLanguage`; Companion names use that same current game-data language behavior as Minion Scaler. |
| MNP-UI-004 | Disable active mapping | With Companion 331 transformed, switch its mapping OFF. On the next Framework update the existing tracked appearance is restored through the normal restoration path and no further target backing is applied while disabled. Re-enable it and verify the normal source-model-ready path reapplies BNpcBase 13910 once. |
| MNP-UI-005 | Mapping isolation | Toggle each row independently. Changing one source row does not alter the enabled state, target selection, appearance, or model scale of any other mapping. |
| MNP-UI-006 | Window lifecycle | Open the window from Dalamud's plugin configuration action, close/reopen it, unload/reload the plugin, and verify there are no duplicate draw callbacks, stale windows, or configuration errors. Visual layout review is User acceptance and remains `UNEXECUTED` until observed in game. |
| MNP-UI-007 | Bulk enable/disable | In the actual configuration window, click the localized enable-all button and verify all four individual mapping controls become enabled and one persisted config update represents the resulting set. Click the localized disable-all button and verify all four controls become disabled, an actively transformed mapped Companion is restored through the existing path, and no mapping is selected while disabled. Re-enable all and verify the normal mapping path resumes. No extra mapping or global runtime mode is created. |

All runtime cases use the actual plugin and FF14 object table. No fixture or synthetic Companion can satisfy MNP-STATE-002 through MNP-STATE-017 or MNP-UI-001 through MNP-UI-007.
